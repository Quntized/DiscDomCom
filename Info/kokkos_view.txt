What you actually need to know about Kokkos::View

Since digging through Kokkos_BasicView.hpp will reveal thousands of lines of complex template metaprogramming, it is better to understand the Public API (how you use it) rather than the internal plumbing.

A Kokkos::View is a Smart, Multi-Dimensional Pointer. It has three key properties ("Template Arguments") that define it.
A. Data Type (The "What")

    What it stores: double, int, Complex, etc.

    Dimensions: You define dimensions using asterisks *.

        double* = 1D Array.

        double** = 2D Array.

        double*** = 3D Array.

B. Layout (The "How")

This defines how the multi-dimensional grid is flattened into 1D computer RAM.

    LayoutRight (Row-Major): The last index changes fastest (e.g., (0,0), (0,1), (0,2)).

        Standard for: C++, CPUs.

        DDC uses this.

    LayoutLeft (Column-Major): The first index changes fastest (e.g., (0,0), (1,0), (2,0)).

        Standard for: Fortran, GPUs (often preferred for memory coalescing).

C. Memory Space (The "Where")

    HostSpace: CPU RAM.

    CudaSpace / HipSpace: GPU VRAM.

    UVMSpace: Unified memory (works on both, but slower).

3. Summary: The "View" Mental Model

When you write:
C++

Kokkos::View<double**, Kokkos::LayoutRight, Kokkos::HostSpace> matrix("my_matrix", 100, 100);

You are creating an object that:

    Allocates 100×100 doubles in CPU RAM (HostSpace).

    Arranges them row-by-row (LayoutRight).

    Manages the memory automatically (like a smart pointer). If you copy matrix, it just copies the pointer (shallow copy). The memory is freed only when the last copy dies.

This is exactly what DDC's Chunk is wrapping. Chunk adds physics domains (grids) on top of this raw Kokkos::View.
